# Phase 3: Screen Wiring

## Requirements
`read_aloud_screen.dart` is rewritten so the passage panel and auto-record hint show during prep, the passage panel and recording indicator show during response, and the upload-status label still shows once recorded — all driven end-to-end by forwarding `ExamAttemptBloc`'s timer snapshots into `ReadAloudCubit`, with no manual start/stop control and no Skip button anywhere.

## Steps
1. In the screen's `State`, after constructing `ReadAloudCubit` as today, immediately forward the bloc's current snapshot to it if `ExamAttemptBloc`'s state is already `AttemptInProgress` **and that state's `task.pinnedItemPublicId` equals `widget.task.pinnedItemPublicId`** (covers resuming mid-task without misfiring for a stale/mismatched task), then subscribe to `ExamAttemptBloc.stream` to forward every later `AttemptInProgress.timerSnapshot` **under the same identity check**; cancel the subscription in `dispose` alongside the existing cubit close.
   - **Required guard (plan-reviewer CRITICAL finding, ACCEPTED):** `TaskTypeDispatcher` keys each task screen by `ValueKey(pinnedItemPublicId)`, but Flutter defers the old Element's `dispose()` to end-of-frame while `ExamAttemptBloc`'s stream delivers the *new* task's `AttemptInProgress` via microtask — meaning the outgoing screen's still-live subscription can receive the incoming task's first snapshot before its own `dispose()` cancels it. This is reachable on every proctor-forced (`TimerTaskAdvancedExternally`) or stale-rejection (`SyncTaskRejectedExternally`) advance, both of which bypass the recorded/upload-gated advance path that would otherwise make the old cubit a safe no-op. Every forward to `onTimerSnapshot` — both the initial one and every stream event — must therefore compare `state.task.pinnedItemPublicId` against `widget.task.pinnedItemPublicId` and silently skip the forward on mismatch, since a mismatched snapshot means this screen instance is already stale and about to be torn down.
2. Replace the placeholder body with the new composition: prep phase renders the passage panel plus the new auto-record hint; response phase renders the passage panel plus the recording indicator, deriving `elapsed`/`total` from the task's `responseSeconds` and the live snapshot's remaining time via a `BlocSelector` mirroring `ExamAppBar`'s existing pattern; the recorded phase keeps rendering the existing upload-status label unchanged.
3. Remove the manual Start/Stop `PrimaryButton` entirely, then remove its two now-dead `AppStrings` entries after a repo-wide search confirms nothing else references them.
4. Repurpose or replace the "not recorded yet" string with prep-phase copy consistent with the new hint text, keeping the recorded-phase upload-status labels untouched.
5. Extend or add the screen-level widget test (mirroring `write_essay_screen_test.dart`'s mocked-`ExamAttemptBloc` setup): passage text renders; the prep-phase hint shows when the mocked bloc's snapshot phase is prep; the recording indicator appears once a new state with a response-phase snapshot is emitted on the mocked bloc's stream (exercising the Step 1 bridge); **and a case asserting a mocked-bloc state whose `task.pinnedItemPublicId` differs from `widget.task.pinnedItemPublicId` is never forwarded to the cubit (e.g. `recorder.start` is never called for it)** — covers the Step 1 identity guard.
6. Confirm the file stays within the repo's line-count limit by actually running `.github/scripts/check-standards.sh` (or, if unavailable in this shell, `(Get-Content <file> | Measure-Object -Line).Lines`) against the rewritten file — not just by reading it — splitting a private widget class into the same file (or a new file) if it exceeds 300 lines, and confirm `ReadAloudAdvanceButton`/`ExamScaffold` usage is unchanged.
7. Run `flutter analyze` and the full touched test suite (Phase 1 unit test, Phase 2 widget tests, and this phase's screen test), fixing any warning or failure before the phase is considered done.

## Success Criteria
- `flutter test test/widget/features/exam_attempt/read_aloud_screen_test.dart` passes, including the prep-to-response transition driven through the mocked bloc's stream.
- `flutter test test/unit/features/exam_attempt/read_aloud_cubit_test.dart` and both Phase 2 widget test files still pass unaffected.
- A repo-wide search finds zero remaining references to the two removed `AppStrings` entries.
- `flutter analyze` is clean across every file touched across Phases 1–3.
- `check-standards.sh` (or an equivalent line-count command actually run, not just eyeballed) confirms the rewritten screen file is ≤300 lines.
- The new screen-level test's mismatched-task case passes: a snapshot for a different `pinnedItemPublicId` never reaches `onTimerSnapshot`/`recorder.start`.
- Reading the rewritten screen confirms: no manual record button, no Skip button, `bottomAction` is still exactly `ReadAloudAdvanceButton`, and `ExamScaffold`/`ExamAppBar`/`ExamBottomBar` chrome is untouched.

## Risks
- **Cross-task misfire (plan-reviewer CRITICAL, fixed by Step 1's identity guard):** a stale screen's still-live subscription can receive the next task's first snapshot before its own `dispose()` runs (reachable via proctor-forced/rejected-submission advances, which bypass the recorded/upload gate) — mitigation is the mandatory `pinnedItemPublicId` equality check on every forward, covered by the new mismatched-task test case.
- Forwarding the snapshot only once at cubit-creation time misses a resume-mid-response case if the bloc's state isn't ready at that exact point: mitigation — perform the initial forward guarded by an `AttemptInProgress` type check in `initState`, immediately after constructing the cubit and before subscribing to the stream.
- Widget-test timing mismatch between `BlocProvider.create` and `context.read<ExamAttemptBloc>()` availability: mitigation — mirror the proven `BlocProvider` + `Builder`-for-inner-context pattern already used in `mc_reading_single_screen.dart`.
- Screen file exceeding the line-count limit once composition and subscription logic are both added: mitigation — extract the body composition into a small private widget class in the same file, as other rewritten screens in this feature already do.
