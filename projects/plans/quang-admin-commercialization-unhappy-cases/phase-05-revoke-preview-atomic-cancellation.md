## Proposed HTTP contract

Digest binds the authenticated actor and code resource, carries issuedAt/expiresAt with a proposed5-minute lifetime, and is verified server-side before locked scope comparison. Another actor/resource, tampering or expired preview cannot authorize mutation; expiration requires409 and fresh preview. Reset acknowledgements after every repreview; retain reason only. Signing-key provisioning/rotation follows existing project secret conventions and is a phase01 compatibility check, never a value committed to docs/source.

GET `/api/v1/admin/license-codes/{publicId}/revoke-preview`:200 safe preview/digest via ApiResponse,401/403 authorization,404 absence. POST `/{publicId}/revoke`: reason + authenticated scope digest + acknowledgements;200 safe metadata/cancellation recap. Missing confirm fields/invalid reason400; direct business reason errors422; changed code/subscription/tenant/effective state OR exact sorted SCHEDULED membership409 with refresh instruction; effective expired410. OPEN/CLOSED informational counts are excluded from digest. No comparison of counts alone can authorize changed membership. Confirm acknowledgements remain mandatory for linked subscription cancellation even when SCHEDULED membership is empty.

No UUID variant is added beneath the legacy String bearer path. Old token revoke endpoint409 until clients upgrade; no token in logs or error. Lock timeout/deadlock gets sanitized existing retryable server classification (phase01 maps actual exception), never generic success or an unbounded mutation retry.
