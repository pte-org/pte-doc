# Plan: Practice skill scope and all-mode retry configuration

## Scope challenge

- **Exists?** Partially. The canonical wizard has exam modes and draft-to-publish flow, but always uses the full template. Attempt delivery currently resumes one active attempt and rejects a submitted attempt; schema enforces one attempt per session/student.
- **Minimum?** Persist a Practice-only skill scope and a host-configured retry count for every mode, make readiness/generation agree, number each immutable attempt and enforce the quota under the existing session lock, expose settings/retry UX, and verify host can inspect submitted answers.
- **Complexity?** Hard: session and attempt persistence/lifecycle, assessment generation, host web, Flutter, compatibility, and authenticated cross-app verification. Keep timer/report policy changes out of this MVP.
- **Mode:** Hard. **Verification:** user requested no unit tests and no quality gate; retain compile/type-check/build checks and the authenticated local walkthrough.

## Objective

Allow hosts to create skill-focused Practice exams and configure the number of retries per student in any exam mode while retaining the existing PTE template as the source of task structure and preserving the canonical exam lifecycle. The success path is a real host-created exam completed and submitted in `pte-app`, with the submitted answers visible in the host interface; report publication is not required.

## Decisions and defaults

- Practice can include one or more sections present in the selected active template. Default to every section in that template so existing behavior is preserved until the host narrows the scope.
- Every exam mode exposes `maxRetriesPerStudent`, an integer from `0` to `9` counting retries after the initial attempt. Default to `0` to preserve existing behavior; the host can raise it while editing a draft.
- Mock Test and Official Exam remain full-template scope in this release. The backend rejects a partial-scope request in either mode; the UI does not offer a partial selector for them.
- Retry configuration is available for `PRACTICE`, `MOCK_TEST`, and `REAL_EXAM` (Official exam); total attempts equal `1 + maxRetriesPerStudent`.
- Add `selectedSkills` additively. On create, omission resolves to the full scope of the template pinned to the draft. On patch, omission preserves current scope except a template change or switch from partial Practice to Mock/Official, which resets to full scope.
- Do not blindly backfill historical sessions as full-template scope: older sessions may have no template reference or may point to a snapshot generated by a different flow. Their existing snapshot remains authoritative; scope metadata may be absent for such legacy rows.
- For a pre-existing DRAFT with a pinned template but no scope rows, resolve missing scope as all sections in that pinned template. For already-generated or template-less historical sessions, leave scope absent and keep the existing snapshot authoritative.
- Persist scope and `maxRetriesPerStudent` with the draft. Both become immutable once the exam is generated/published under existing draft lifecycle rules.
- Assessment owns a single resolver used by preflight and deterministic generation. The same selected sections must drive shortage calculation and item selection.
- Each full-exam submission is a distinct `ExamAttempt` with an increasing `attemptNumber`, pinned to the same immutable generated form. Never reset or overwrite a submitted attempt.
- Under the session-row lock, resume a `CREATED`/`IN_PROGRESS` attempt; otherwise allow a new attempt only when submitted count is below `1 + maxRetriesPerStudent`. Only `SUBMITTED` attempts consume the configured total (including timer-expiry submission).
- Every new attempt receives a fresh timer based on the template/pinned task timing. Do not add an untimed option or reinterpret unlimited audio replay as unlimited attempts.
- Keep report publication out of the demo. A future student-report release must decide whether multiple attempts publish all results, latest, or best.
- `pte-app` consumes the server-generated snapshot without section filtering. Only make its completion heading neutral if needed for non-Reading single-skill exams.

## Critical path

1. Add and persist additive scope and retry-count contracts; migrate historical attempts to `attemptNumber=1`.
2. Make preflight and deterministic generation honor exactly the persisted scope.
3. Enforce the submission quota and create a new immutable, numbered attempt per allowed retry.
4. Add Practice skill and all-mode retry settings to the host wizard and allowed-retry/limit-reached UX to `pte-app`; distinguish attempt numbers in host answers.
5. Run compile/type-check/build checks and the authenticated host → app → host walkthrough using local data. Unit tests and quality gates are explicitly skipped per user request.

## Out of scope / defer

- Untimed Practice, changed per-task timing, or immediate feedback.
- Task-type-level filters, arbitrary per-exam question counts, template editing, or new scoring behavior.
- Changes to other Mock/Official policy presets, billing/entitlements, audience or overlap rules, examiner assignment, and report-publication authorization.
- Re-enabling the legacy skills-only route or adding client-side filtering in `pte-app`.

## Risks and mitigations

- **Preflight/generation drift:** If readiness checks the entire template while generation filters skills (or vice versa), hosts receive false blockers or generation failures. Use the same assessment-side scope resolver and test both paths against identical requirements.
- **Draft compatibility:** Existing API clients may omit `selectedSkills`. On create, default omission to the full pinned-template scope; on ordinary patches preserve current scope. Do not mutate historical/template-less sessions or assume their snapshots contain all four skills.
- **Mode changes:** Switching a partial Practice draft to Mock/Official without an explicit partial scope restores the full template scope. An explicitly submitted partial scope for a non-Practice mode remains a validation error.
- **Mode bypass:** A caller may send a partial scope with Mock/Official. Enforce the full-template rule on the backend, not just by hiding the UI control.
- **Snapshot/report integrity:** Do not filter at delivery time. Generate the scoped immutable snapshot so task totals, scoring, and reports agree.
- **Attempt history integrity:** Reusing an `ExamAttempt` would overwrite answer/pin history and conflicts with answer identity. Use a new row per submission, backfill existing rows as attempt 1, and retain attempt-level IDs. The session lock already serializes start operations; keep quota check and row creation inside that locked transaction.
- **Report policy deferred:** Existing report publication fans out across every submitted attempt. It is deliberately excluded from this demo; before enabling student report publication for multi-attempt sessions in any mode, define which attempts students can see.
- **Timer and duplicate-start behavior:** A retry starts a fresh template-defined timer. Start/resume must be idempotent for an active attempt so duplicate app requests do not consume extra attempts.
- **Demo data/device risk:** Validate local question stock and subscriptions before the walkthrough. Use one existing student and a no-microphone skill for the primary manual path; keep selected-scope logic covered for all supported sections in automated tests.
- **Existing worktree change:** Preserve the unrelated modified `QuestionRepositoryTest.java`; report any unrelated failing test rather than editing it as part of this plan.

## Release / rollback

- Additive migration and request fields; deploy API before the updated host web client.
- Old clients continue to create full-template exams by omitting `selectedSkills`; omitted retry count defaults to `0`.
- If the new selector or scope-aware preflight is blocked, do not route through the legacy endpoint. Revert the feature release or use the existing full-template Practice path for the demo.
- No local database reset or destructive seed cleanup is part of this plan.
