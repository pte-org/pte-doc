# Phase 1: Content audit and gap fill

**Goal:** Know exactly which of the 22 task types have usable question content and author the rest.

## Tasks

1. Produce a coverage table (task type x: in approved seed? in `local-question-seed-150.sql`? usable media fixture? passes `QuestionValidationHelper` rules from `PteTaskType`).
2. For the 5 gap types — `DESCRIBE_IMAGE`, `SUMMARIZE_GROUP_DISCUSSION`, `SUMMARIZE_SPOKEN_TEXT`, `FILL_IN_THE_BLANKS_TYPE_IN`, `HIGHLIGHT_INCORRECT_WORDS` — build demo content as JSON in the same shape as `by-task-type/*.json` (prompt text, correct answer / options, word-count bounds):
   - SST, FIB-TypeIn, DI: read audio/image URLs and transcripts from `pte.netlify.app` pages (browser DOM, read-only; choose 3 per type).
   - HIW: take 3 site audios that have a transcript, alter 3-5 words in the shown text, store the altered words as the answer.
   - SGD: 2 local fixtures from `pte-doc/projects/fixtures/question-media/question-media-map.md` + 1 more audio; write the 3 scenario titles.
   - Record each URL's `Content-Type`/duration from the HTTP HEAD response only if needed by the `media_objects` columns.
3. Target count is fixed at **3 questions per type** (user decision), 66 total, including types whose table count is lower (WE 1, SST 1, SWT 2, SMW 2): the bank has 3 and the template count picks from them.
4. Write the curated selection as one deterministic file (`pte-doc/data/question-import/demo-22-selection.json`): stable title per question (`DEMO22 - <TASK_KEY> - <n>`) so reruns can find existing rows.

## Design Constraints

- Never invent official Pearson content; mark authored items as demo content in the title.
- Do not edit the canonical `by-task-type/*.json` (generated by `tools/sync-clean-question-data.js`); add a separate file.
- Option rules from `QuestionValidationHelper`: unique non-negative `orderIndex`; `RE_ORDER_PARAGRAPHS` uses `orderIndex` as the correct position; single-answer types need exactly one correct option; `FILL_IN_THE_BLANKS_DROPDOWN` options must use globally unique `orderIndex` (blank scope is `blankIndex`).
- Word-count bounds are required for `SUMMARIZE_WRITTEN_TEXT`, `WRITE_ESSAY`, `SUMMARIZE_SPOKEN_TEXT` and the listening types flagged in `PteTaskType`.

## Success Criteria

- Coverage table committed in the plan folder; every one of the 22 types has >= target count candidates, each pre-validated against the enum rules by a small script or checklist.
