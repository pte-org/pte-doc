# Phase 1: Unify Cubit/State (`AutoRecordCubit`/`AutoRecordState`)

## Requirements
`ReadAloudScreen` and `RepeatSentenceScreen` behave identically to today (byte-for-byte, verified by the existing regression suite), but both now run on one shared `AutoRecordCubit`/`AutoRecordState` instead of two duplicate cubit/state pairs — clearing the way for `DescribeImageScreen` to reuse the same cubit in Phase 4 without a 3rd duplicate.

## Steps
1. Create `lib/features/exam_attempt/presentation/cubit/auto_record_state.dart`: `AutoRecordState` (`recordingPhase`, `uploadStatus`) implementing `UploadTrackingState`, `export 'recording_phase.dart';` preserved (screens currently get `RecordingPhase` transitively through this export). Merge/update the doc comment to say it's shared by every auto-record speaking screen (Read Aloud, Repeat Sentence, and — once Phase 4 lands — Describe Image), not "originally lived under `ReadAloudState`."
2. Create `lib/features/exam_attempt/presentation/cubit/auto_record_cubit.dart`: `AutoRecordCubit extends Cubit<AutoRecordState>` plus the top-level `Future<String> resolveRecordingFilePath(String attemptPublicId, String pinnedItemPublicId)` function (renamed from `resolveReadAloudFilePath`, relocated here, doc comment and body byte-for-byte identical). Copy the full class body from `ReadAloudCubit` verbatim: constructor + field wiring, the `_startInFlight`/`_stopInFlight` guard fields and their doc comment, `onTimerSnapshot` and its doc comment (including the `_nonNegative` clamp note), `startRecording`, `stopRecording` (including the "failed re-record preserves recorded phase" comment), `close`. Do not re-derive any of this logic from scratch — copy it.
3. Delete `lib/features/exam_attempt/presentation/cubit/read_aloud_cubit.dart`, `read_aloud_state.dart`, `repeat_sentence_cubit.dart`, `repeat_sentence_state.dart`.
4. Update `lib/features/exam_attempt/presentation/cubit/recording_phase.dart`'s doc comment: replace the `ReadAloudState`/`RepeatSentenceState` reference with `AutoRecordState` (the enum itself is unchanged — it already lives in its own file and is already re-exported).
5. Update `lib/features/exam_attempt/presentation/pages/speaking/read_aloud_screen.dart` and `repeat_sentence_screen.dart`: swap every `ReadAloudCubit`/`ReadAloudState` (resp. `RepeatSentenceCubit`/`RepeatSentenceState`) reference — imports, field types, constructor calls, `BlocProvider.value`/`BlocBuilder`/`BlocSelector` type params, and the `AutoAdvanceOnUploadReady<C, S>` type arguments — to `AutoRecordCubit`/`AutoRecordState`. No behavioral change; this step is a pure rename/re-type pass. (Timer-bridge boilerplate itself is untouched here — that's Phase 2.)
6. Update `test/widget/features/exam_attempt/auto_advance_on_upload_ready_test.dart`: rename `_MockReadAloudCubit` to `_MockAutoRecordCubit implements AutoRecordCubit`, swap `ReadAloudState`/`ReadAloudCubit` references to `AutoRecordState`/`AutoRecordCubit`, and update its doc comment (currently says "the generic widget has no logic that varies by type parameter... exercised via one concrete binding") to note it's now shared by all 3 auto-record screens through the same single binding.
7. Create `test/unit/features/exam_attempt/auto_record_cubit_test.dart`: merge `read_aloud_cubit_test.dart` + `repeat_sentence_cubit_test.dart` into one deduped suite against `AutoRecordCubit`/`AutoRecordState` — since the two source files test byte-identical behavior (nothing in the cubit is task-type-specific), the merged suite should cover each distinct branch exactly once: the 4 recording-phase-transition cases (start emits recording, stop success emits recorded + upserts + triggers upload, stop-null-from-fresh falls back to idle, failed re-record preserves recorded) and the 7 `onTimerSnapshot` cases (idle+response starts, recording+response+expired stops, prep is a no-op, already-recorded is a no-op, resume-after-expiry starts-only, non-expired mid-recording tick is a no-op, and both back-to-back-no-await guard-race tests). Delete `read_aloud_cubit_test.dart` and `repeat_sentence_cubit_test.dart`.
8. Run the full test suite and `flutter analyze`; fix any remaining stale reference (grep for `ReadAloudCubit`, `ReadAloudState`, `RepeatSentenceCubit`, `RepeatSentenceState`, `resolveReadAloudFilePath` across `lib/` and `test/` — every hit must be gone or intentionally updated).

## Success Criteria
- `grep -rn "ReadAloudCubit\|ReadAloudState\|RepeatSentenceCubit\|RepeatSentenceState\|resolveReadAloudFilePath" lib/ test/` returns no matches.
- `flutter analyze` is clean (no new errors/warnings introduced).
- Full test suite run reports 0 failures. Record the actual pass count in `plan.md`'s Session Notes (baseline before this phase: 273/273; expect a net reduction from deduping the 22 near-identical cubit-test cases down to 11 distinct ones — document the real delta, don't assume it).
- The pre-existing `read_aloud_screen_test.dart` (5 tests) and `repeat_sentence_screen_test.dart` (7 tests, including the 3 sub-stage cases) pass unchanged — same assertions, same text expectations, 0 modifications needed to those two files in this phase.
- `auto_advance_on_upload_ready_test.dart`'s 3 tests pass against the new `AutoRecordCubit`/`AutoRecordState` binding.

## Risks
- Copy-paste drift between the two original cubits during the merge (there is none today, but a careless merge could introduce one): Mitigation — diff `ReadAloudCubit` and `RepeatSentenceCubit` line-by-line before deleting either; they must be identical except for doc-comment wording before the merge is trusted.
- Losing the `_startInFlight`/`_stopInFlight` guard's exact semantics (checked-and-set synchronously before the first `await`, cleared on completion via `whenComplete`) during the copy: Mitigation — copy verbatim, and keep the two back-to-back-no-await guard-race tests in the merged suite as the regression gate for this specific behavior.
- `RecordingPhase` becoming unreachable in a screen that relied on the old state file's `export` if the export isn't preserved: Mitigation — explicitly verified in Step 1/Success Criteria via `flutter analyze` clean (a missing export would surface as an undefined-name compile error).
