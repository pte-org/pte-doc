# Phase 4: `DescribeImageScreen` + Dev Fixture + Dispatcher Wiring

## Requirements
A working `DESCRIBE_IMAGE` screen: instruction text interpolating both `prepSeconds` and `responseSeconds`, the shared single status card, and a real displayed image below it — fully automatic recording and advance, selectable from the dev preview picker, routed correctly by `TaskTypeDispatcher`.

## Steps
1. Create `lib/features/exam_attempt/presentation/pages/speaking/describe_image_screen.dart`: `DescribeImageScreen extends StatefulWidget` with the same constructor shape as `ReadAloudScreen` (`task`, `attemptPublicId`, `recorder`, `mediaDao`, `coordinator`, `syncEngine`). `_DescribeImageScreenState` uses `with AutoRecordTimerBridgeMixin<DescribeImageScreen>`, constructs an `AutoRecordCubit` in `initState`, calls `startAutoRecordBridge(...)`, and mirrors `ReadAloudScreen`'s `dispose`/`build` shape exactly (`BlocProvider.value` + `ExamScaffold` + `AutoAdvanceOnUploadReady<AutoRecordCubit, AutoRecordState>` as `bottomAction`).
2. Body (`_DescribeImageBody`, mirroring `_ReadAloudBody`'s structure): `InstructionText(text: ...)` built from `AppStrings.describeImageInstructionPrefix/Middle/Suffix` interpolating `task.prepSeconds` then `task.responseSeconds` → `SizedBox` spacing → `AutoRecordStatusCard(task: task, recordingState: state, snapshot: snapshot)` → `SizedBox` spacing → the image region.
3. Image region: if `task.imagePromptRef` is non-null, render `TaskImageDisplay(imageUrl: task.imagePromptRef!)`; if `null`, render a graceful fallback (`Text(AppStrings.taskImageMissingLabel)`) instead of crashing — document inline that a real `DESCRIBE_IMAGE` task always carries an image per PTE's task definition, so a `null` here is treated as a fixture/data error, not a normal runtime state to design deeply around.
4. Add `SpeakingWritingTaskFixtures.describeImage` to `lib/features/exam_attempt/dev/speaking_writing_task_fixtures.dart`: `prepSeconds: 25`, `responseSeconds: 40` (literal, per this plan — do not round for poll-boundary convenience), `imagePromptRef: 'https://picsum.photos/seed/describe-image-fixture/800/600'`. Doc comment mirrors `repeatSentence`'s existing poll-boundary-lag doc comment (documents up to ~5s of dev-preview-only UI lag at the prep→response and response→recorded transitions, explains why, and states this is never a production concern), plus a new note that this fixture — unlike every other one in this file — requires real network connectivity in dev preview. Add `describeImage` to `SpeakingWritingTaskFixtures.all`.
5. Wire `lib/features/exam_attempt/presentation/widgets/task_type_dispatcher.dart`: add `const String _taskTypeDescribeImage = 'DESCRIBE_IMAGE';` and a switch case mirroring `_taskTypeReadAloud`'s exact argument-passing pattern (`key`, `task`, `attemptPublicId`, `recorder: audioRecorderService`, `mediaDao`, `coordinator: mediaUploadCoordinator`, `syncEngine`), importing `describe_image_screen.dart`.
6. Create `test/widget/features/exam_attempt/describe_image_screen_test.dart` mirroring `read_aloud_screen_test.dart`'s shape and fixture-construction pattern (including the `_FakePathProviderPlatform` setup for `resolveRecordingFilePath`'s `path_provider` dependency): instruction text renders with both `prepSeconds` and `responseSeconds` interpolated correctly; prep phase shows the "Beginning in…" card and never starts recording; a response-phase snapshot auto-starts recording and shows the "Recording… seconds left" card; the full prep→response→recorded transition stops the recorder and shows the upload-status card; a `pinnedItemPublicId` mismatch is never forwarded (identity-guard regression test, same as the other 2 screens); the image renders via `TaskImageDisplay` with the task's `imagePromptRef`; a `null` `imagePromptRef` renders the fallback message instead of throwing.
7. Update `test/widget/features/exam_attempt/task_type_dispatcher_test.dart`: add a `DESCRIBE_IMAGE` routing test group mirroring the existing `REPEAT_SENTENCE` routing group (routes to `DescribeImageScreen`, not the unsupported-task-type placeholder).
8. Run the full test suite and `flutter analyze`.

## Success Criteria
- `flutter analyze` is clean.
- `describe_image_screen_test.dart` passes in full (all 7 cases from Step 6).
- `task_type_dispatcher_test.dart`'s new `DESCRIBE_IMAGE` routing test passes.
- Full test suite: 0 failures. Record the actual count in `plan.md`'s Session Notes.
- Manual dev-preview check (documented in Session Notes, not automatable): selecting the `SPEAKING — DESCRIBE_IMAGE` fixture from the picker shows the instruction text with "In 25 seconds... You will have 40 seconds...", the status card cycling through its 3 states, and the Food-Pyramid-style placeholder image loading below it (requires network connectivity).
- `grep -n "Text('" lib/features/exam_attempt/presentation/pages/speaking/describe_image_screen.dart` returns no matches.

## Risks
- Forgetting the `_FakePathProviderPlatform` setup in the new screen test (required because `AutoRecordCubit`'s default `resolveRecordingFilePath` calls `path_provider`): Mitigation — copy the exact `setUpAll`/`_FakePathProviderPlatform` block from `read_aloud_screen_test.dart`.
- `imagePromptRef` null-handling being untested and silently crashing in production for a malformed fixture/backend response: Mitigation — Step 6's dedicated null-`imagePromptRef` test case is a required part of this phase's gate, not optional.
- Divergence between `DescribeImageScreen`'s body structure and `ReadAloudScreen`'s (e.g. forgetting the `Expanded`/`SingleChildScrollView` wrapping needed once `AppDimensions.taskImageDisplayHeight` is added) causing a layout overflow error: Mitigation — widget test pump with `tester.pumpAndSettle()` or a bounded test harness height will surface a `RenderFlex` overflow immediately if present; treat any layout exception in the new test file as a hard failure, not a warning.
