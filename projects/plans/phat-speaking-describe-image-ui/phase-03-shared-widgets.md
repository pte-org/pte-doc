# Phase 3: Shared Widgets — `TaskImageDisplay` + `AutoRecordStatusCard` + New Strings/Dimensions

## Requirements
Two new reusable, props-only presentational widgets exist and are covered by their own widget tests: `TaskImageDisplay` (renders a task's image via `Image.network` with loading/error states, never crashes) and `AutoRecordStatusCard` (the single-card recorded/response/prep state machine, extracted out of `ReadAloudScreen`'s private `_StatusCard` so Describe Image can reuse it in Phase 4 without a 3rd duplicate). `ReadAloudScreen` is refactored onto the extracted widget with zero behavioral change.

## Steps
1. Add new `AppStrings` constants: `describeImageInstructionPrefix = 'Look at the image below. In '`, `describeImageInstructionMiddle = ' seconds, please speak into the microphone and describe in detail what the image is showing. You will have '`, `describeImageInstructionSuffix = ' seconds to give your response.'` (interpolated as `prefix + prepSeconds + middle + responseSeconds + suffix` — unlike Read Aloud's template, which interpolates `responseSeconds` twice, this one genuinely uses both `task.prepSeconds` and `task.responseSeconds`), `taskImageLoadErrorLabel` (shown when `Image.network` fails to load), and `taskImageMissingLabel` (shown when `TaskView.imagePromptRef` is `null` — a fixture/data-error fallback, not a crash, since real `DESCRIBE_IMAGE` tasks always carry an image per PTE's task definition).
2. Add `AppDimensions.taskImageDisplayHeight` (e.g. `240.0`) so `TaskImageDisplay` renders inside a bounded height — required for `Image.network`'s `loadingBuilder` (`CircularProgressIndicator`) to lay out correctly before the real image's intrinsic size is known.
3. Create `lib/features/exam_attempt/presentation/widgets/task_image_display.dart`: `TaskImageDisplay extends StatelessWidget` with `{required String imageUrl}` — no BLoC/context reads, pure props, matching `RecordedAnswerStatusCard`'s existing style. Wrap `Image.network(imageUrl, loadingBuilder: ..., errorBuilder: ...)` in a `SizedBox(height: AppDimensions.taskImageDisplayHeight, ...)`; `loadingBuilder` shows a centered `CircularProgressIndicator` while `frame == null`; `errorBuilder` shows a centered `Text(AppStrings.taskImageLoadErrorLabel)` and never rethrows.
4. Create `lib/features/exam_attempt/presentation/widgets/auto_record_status_card.dart`: `AutoRecordStatusCard extends StatelessWidget` with `{required TaskView task, required AutoRecordState recordingState, required TimerSnapshot? snapshot}` — port `ReadAloudScreen`'s private `_StatusCard` build method, `_countdownLabel`, `_elapsedFraction`, and `_uploadStatusLabel` helpers verbatim (same 3-branch logic: recorded always wins → live response countdown with elapsed-fraction progress → live prep countdown with progress forced to `0.0`). Document in the widget's doc comment why this was extracted now (2nd occurrence today via Describe Image, would have been a 3rd if any future screen needed the same shape) and why `RepeatSentenceScreen`'s `_RecordCard` is deliberately **not** merged into it (its pre-record sub-stage clamping genuinely diverges from this simpler shape).
5. Refactor `lib/features/exam_attempt/presentation/pages/speaking/read_aloud_screen.dart`: delete the private `_StatusCard` class and its helper methods; `_ReadAloudBody` now builds `AutoRecordStatusCard(task: task, recordingState: state, snapshot: snapshot)` in its place. No other change to `_ReadAloudBody`'s structure.
6. Create `test/widget/features/exam_attempt/task_image_display_test.dart`: verify `TaskImageDisplay` builds an `Image` widget backed by a `NetworkImage(imageUrl)` for the given `imageUrl` prop (widget-tree inspection, not a real network fetch — matches this project's convention of not mocking network calls in widget tests), and verify the widget tree includes the bounded `SizedBox` height so no unbounded-constraint layout error occurs when pumped standalone inside a `MaterialApp`/`Scaffold`.
7. Create `test/widget/features/exam_attempt/auto_record_status_card_test.dart`: port the 3-branch coverage this logic already has indirectly through `read_aloud_screen_test.dart` (prep shows "Beginning in…" with `progress: 0.0`; response shows the live "Recording… seconds left" label with the correct elapsed fraction; `recorded` phase always wins regardless of the live snapshot's phase, showing the upload-status label with `progress: 1.0`) directly against the extracted widget, independent of any screen.
8. Run the full test suite and `flutter analyze` — `read_aloud_screen_test.dart`'s existing assertions (unchanged) are the regression gate proving the extraction didn't alter Read Aloud's rendering.

## Success Criteria
- `flutter analyze` is clean.
- New files `task_image_display_test.dart` and `auto_record_status_card_test.dart` pass, 0 failures.
- `read_aloud_screen_test.dart`'s existing 5 tests pass unchanged (same text expectations: `'Beginning in 10 seconds'`, `'Recording 40 seconds left'`, `'Still uploading…'`) — proves `AutoRecordStatusCard` reproduces `_StatusCard`'s exact output.
- Full test suite: 0 failures. Record the actual count (baseline: end-of-Phase-2 count + the new tests added here) in `plan.md`'s Session Notes.
- `grep -rn "Text('" lib/features/exam_attempt/presentation/widgets/task_image_display.dart lib/features/exam_attempt/presentation/widgets/auto_record_status_card.dart` returns no matches (every label goes through `AppStrings`).

## Risks
- `Image.network`'s `errorBuilder`/`loadingBuilder` callbacks are hard to trigger deterministically in a widget test without a real network round-trip: Mitigation — scope the widget test to structural assertions (correct `NetworkImage` URL, bounded layout) rather than asserting on a real load/error outcome; this matches how the rest of this codebase avoids network mocking in tests.
- Extracting `AutoRecordStatusCard` introduces an off-by-one or sign error in `_elapsedFraction`/`_countdownLabel` during the port: Mitigation — copy verbatim, do not "clean up" the math; `read_aloud_screen_test.dart`'s exact-text assertions catch any drift immediately.
- `AppDimensions.taskImageDisplayHeight` being wrong for real Describe Image images (too small/cropped) is a visual/UX concern, not a correctness one: Mitigation — deferred to visual QA in Phase 4/5; not a blocking gate for this phase.
