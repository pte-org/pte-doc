# ADR-001: Modular monorepo with separate API and Worker deployables
**Date:** 2026-06-20
**Status:** Accepted

## Context
APTIS LMS has strong transactional coupling across tenant, enrollment, exam and scoring data, but AI, email and analytics jobs have different latency and failure profiles from critical exam writes.

## Decision
We will build a NestJS modular monorepo with independently deployable `api` and `worker` applications sharing bounded-context libraries. We will not split bounded contexts into network microservices in v1.

## Consequences
### Positive
- Worker backlog cannot consume API request capacity.
- Shared domain contracts avoid duplicated tenant and exam rules.
- Context boundaries remain extraction seams for later services.

### Negative / Trade-offs
- A shared database requires disciplined ownership rules.
- Repository builds and tests can grow without affected-project tooling.

### Risks
- Accidental cross-context imports can create a distributed monolith later; enforce dependency rules in lint/architecture tests.
