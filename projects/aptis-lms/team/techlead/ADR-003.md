# ADR-003: JWT access tokens with rotating server-side refresh sessions
**Date:** 2026-06-20
**Status:** Accepted

## Context
Clients require low-latency authentication across Web and Desktop while administrators must revoke sessions and force logout users.

## Decision
We will issue JWT access tokens with a maximum 15-minute lifetime and opaque rotating refresh tokens with a maximum 7-day lifetime. Only refresh-token hashes and rotation chains are persisted.

## Consequences
### Positive
- API access-token verification is fast and stateless.
- Refresh reuse detection, revocation and force logout remain possible.
- Raw long-lived credentials are absent from the database.

### Negative / Trade-offs
- Rotation adds transactional session logic and race handling.
- Permission changes may require access-token revocation/version checks for immediate effect.

### Risks
- Token replay; revoke the entire rotation family when a replaced token is reused.
