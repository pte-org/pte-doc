# ADR-002: PostgreSQL tenant-column model with row-level security
**Date:** 2026-06-20
**Status:** Accepted

## Context
The platform requires strict tenant isolation, ACID exam writes, JSONB question payloads and cross-tenant Vendor reporting.

## Decision
We will use managed PostgreSQL with `tenant_id` on every tenant-owned record, repository-level scoping, and PostgreSQL RLS as defense in depth. Vendor-global data remains explicitly unscoped and accessible only through privileged application paths.

## Consequences
### Positive
- One migration stream and efficient shared infrastructure.
- Strong relational constraints and transactional exam state.
- RLS catches missing application predicates.

### Negative / Trade-offs
- Vendor queries and background jobs need carefully audited privileged contexts.
- Every connection transaction must set and clear tenant context safely.

### Risks
- Connection-pool context leakage; set tenant context transaction-locally and test hostile cross-tenant access.
